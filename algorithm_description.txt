ViReMa Algorithm Description (minimap2 Backend)
================================================
Covers: ViReMa.py, Minimap2_Module.py, Compiler_Module.py, ConfigViReMa.py
Relevant invocations:
  1. python ViReMa.py --Aligner minimap2            (short-read mode)
  2. python ViReMa.py --Aligner minimap2 -lr ont    (Oxford Nanopore mode)
  3. python ViReMa.py --Aligner minimap2 -lr pb     (PacBio CLR mode)
  4. python ViReMa.py --Aligner minimap2 -lr hifi   (PacBio HiFi mode)

------------------------------------------------------------------------
OVERVIEW
------------------------------------------------------------------------
ViReMa (Virus Recombination Mapper) detects viral recombination events
by splitting sequencing reads across multiple genomic alignments. The
minimap2 backend achieves this by a two-stage strategy:

  Stage 1 - Alignment: minimap2 aligns all reads. Any read that aligns
  only partially (i.e. produces a soft-clipped SAM record) has its
  unaligned portion extracted and re-aligned in one or more subsequent
  rounds. This iterative extraction-and-realignment finds the second
  (and further) segments of a split read.

  For long-read modes (ont/pb/hifi) there is a preliminary step before
  extraction: minimap2 frequently represents a chimeric read (foreign
  content spliced in, a cross-segment fusion, a tandem duplication, an
  inversion) as ONE alignment with the extra content folded into a
  single large embedded 'I' CIGAR operation, rather than splitting into
  primary+supplementary records -- there is then no softclip for the
  extraction step below to ever notice.
  rewrite_embedded_insertions_as_softclips() finds one qualifying
  embedded 'I' per record (longer than MicroInDel_Length and at least
  SEED_THRESHOLD) and rewrites it into an explicit trailing softclip,
  run on every round's own output. When that softclip is then
  extracted, it is split into two independent realignment candidates --
  the insertion content alone, and everything after it alone -- rather
  than realigned as one glued fragment; see "PHASE 2/3" notes below for
  why.

  Stage 2 - Compilation: Compiler_Module.py reads the ViReMa-formatted
  SAM file and tallies recombination junctions, deletions, insertions,
  and copy-back events into text and BED output files.

The four invocation modes differ only in the minimap2 preset used
for the initial and re-alignment steps and how softclipped reads are
selected for re-alignment. All three long-read modes (ont/pb/hifi) now
share the same iterative re-alignment pipeline and the same embedded-
insertion rewrite; PacBio CLR/HiFi previously used a single non-iterated
round with the whole-read preset reused for softclip rescue, which was
found to fail outright on short extracted fragments, and were unified
with ONT's short-fragment-tuned, iterative approach.


------------------------------------------------------------------------
PHASE 0 - ARGUMENT PARSING AND SETUP  (ViReMa.py: MainArgs())
------------------------------------------------------------------------
Relevant config variables (ConfigViReMa.py) set by MainArgs():

  cfg.Lib1          - Path to virus reference FASTA
  cfg.File1         - Path to input reads (FASTQ or FASTA)
  cfg.File3         - Name of the output SAM file
  cfg.Output_Dir    - Output directory (default: working directory)
  cfg.Aligner       - Set to 'minimap2' by --Aligner minimap2
  cfg.LongReadTech  - '' (short read), 'ont', 'pb', or 'hifi';
                      set by -lr flag only when Aligner == 'minimap2'
  cfg.Seed          - Minimum aligned length to accept a segment mapping
                      (default 25 nt); used as SEED_THRESHOLD in
                      Minimap2_Module
  cfg.Chunk         - Number of reads per processing chunk (default 1M)

Index building: for minimap2, ViReMa does not pre-build any index -- the
reference FASTA is passed directly to minimap2 on every invocation (each
round uses different -k/-w flags, and a prebuilt .mmi index bakes those
parameters in at build time, silently overriding whatever the command line
requests; an earlier version of this pipeline built and reused a .mmi index,
which was found to cause exactly this problem, and the index-build step was
removed).


------------------------------------------------------------------------
SITUATION 1: python ViReMa.py --Aligner minimap2
             (Short-Read Mode, LongReadTech = None)
------------------------------------------------------------------------

Step 1 - Initial alignment (Minimap2_Module.py: build_minimap2_command,
                             long_read_tech=None, is_initial=True)

  Command:
    minimap2 -ax sr -k 20 -A 1 -B 2 -O 1,1 -E 1,1 -r 100 -g 2000
             -z 2000,1000 -f 0.0001 -n 1 -p 0.05 -N 5 -s 5 -t 8
             --end-bonus 0 <Lib1> <File1>
    Output written to: output.sam

  Parameter rationale:
    -ax sr         - short-read preset (splice-unaware, high sensitivity)
    -k 20          - k-mer size suitable for accurate short reads
    -A/-B 1/2      - low mismatch penalty encourages longer alignments
    -O 1,1 -E 1,1  - very low gap penalties (viral genomes may have
                     small indels that should not break the alignment)
    -r 100         - bandwidth for chaining
    -g 2000        - max intron/gap size during chaining
    -z 2000,1000   - Z-drop for extension
    -f 0.0001      - minimizer frequency threshold (reduces repetitive hits)
    -n 1 -p 0.05   - minimum chaining seeds and secondary alignment ratio
    -N 5           - up to 5 secondary alignments retained
    -s 5           - minimum DP score
    --end-bonus 0  - no bonus for aligning to read ends

Step 2 - Identify soft-clipped primary alignments
  (Minimap2_Module.py: parse_sam_for_softclipped, long_read_tech=None)

  Reads output.sam and keeps every record that:
    - is a primary alignment (FLAG bit 2048 not set), AND
    - contains an 'S' operation in its CIGAR string.
  When the same read name appears multiple times (multiple primary
  records), the first record encountered is used.

Step 3 - Extract soft-clipped sequences
  (Minimap2_Module.py: extract_softclipped_from_cigar_with_positions)

  For each soft-clipped read:
    - The CIGAR is parsed to locate each 'S' operation.
    - Soft-clipped sequences are labeled with a position index:
        _softclip_0  if the clip precedes the main aligned region
        _softclip_1  if the clip follows the main aligned region
    - Only sequences >= SEED_THRESHOLD (default 25 nt) are kept.
    - All qualifying sequences are written to TEMP_READS.txt in
      FASTA format as:
        >ReadName_softclip_<0|1>
        <clipped sequence>

Step 4 - Second-round alignment
  (Minimap2_Module.py: build_minimap2_command, long_read_tech=None,
   is_initial=False)

  Command:
    minimap2 -ax sr -k 10 -w 5 -m 10 -n 2 -A 2 -B 2 -O 2,4 -E 2,1
             --end-bonus 5 -s 20 -z 200 -r 50
             <Lib1> ./Test_Data/TEMP_READS.txt
    Output written to: TEMP_SAM

  Compared with Round 1, this uses a smaller k-mer (-k 10) and a
  tighter search window (-w 5, -z 200 -r 50) appropriate for the
  shorter, already-trimmed soft-clip sequences.

Step 5 - Merge TEMP_SAM into output.sam
  (Minimap2_Module.py: merge_temp_sam_to_output)

  For each base read name that has softclip sub-reads in TEMP_SAM:
    - All alignments for each softclip identifier are collected.
    - The alignment with the highest AS (alignment score) tag is
      selected.
    - The selected softclip alignments are appended immediately after
      the original primary alignment line for that base read.

  output.sam now contains, for each split read, the primary alignment
  followed by the softclip sub-alignment(s).

Step 6 - Convert to ViReMa format
  (Minimap2_Module.py: convert_to_virema_format)

  Two-pass processing of output.sam:
    Pass 1: Group all SAM records by base read name.
    Pass 2: For each base read name:
      - If the read has only one record (no softclip alignments mapped),
        the record is passed through with its softclips preserved.
      - If the read has multiple records (the main alignment plus one or
        more softclip alignments), merge_split_alignments() is called:

          a. Classify records:
               - Records without _softclip_ in name and not
                 supplemental (FLAG & 2048 == 0) are primary candidates.
               - Records with _softclip_ in name are softclip segments;
                 their position in read-sequence space is computed
                 (0.4 = before main, 0.6 = after main, with recursive
                 sub-intervals for nested clips).
             The primary candidate with the highest AS score is chosen
             as the main alignment.

          b. Sort segments by their sequence-space position (seq_pos).

          c. Group contiguous segments: consecutive segments on the same
             reference sequence with non-overlapping coordinates are
             joined with an N gap in the CIGAR; segments on different
             references (or with overlapping/back-splice coordinates)
             form separate records.

          d. Single contiguous group -> one merged SAM record:
               CIGAR = <seg1_ops>[<gap>N<seg2_ops>...]
               Softclip positions accounted for by a downstream
               softclip alignment are removed from the CIGAR; positions
               not accounted for become insertions (if internal) or
               softclips (if at the global read ends).

          e. Multiple groups -> paired SAM records (primary + one or
             more supplementary, FLAG=2048):
               Each record carries beginning/end hard clips (H) that
               represent the portions of the read covered by the other
               records, and FI:i (fragment index) and TC:i (total count)
               tags.

      Post-processing on every converted read:
        - Internal softclips (S operations not at the first or last
          position of the CIGAR) are converted to insertions (I).
        - Hardclipped nucleotides are removed from the SEQ and QUAL
          fields so the sequence matches the CIGAR.

  Converted reads are written in chunks (default 1 M reads) to the
  final output SAM (cfg.Output_Dir + cfg.File3).

Step 7 - Compilation  (Compiler_Module.py: ResultsSort)
  See the "Compilation" section at the end of this document.


------------------------------------------------------------------------
SITUATION 2: python ViReMa.py --Aligner minimap2 -lr ont
             (Oxford Nanopore Mode, LongReadTech = 'ont')
------------------------------------------------------------------------

Step 1 - Initial alignment (build_minimap2_command, long_read_tech='ont',
                             is_initial=True)

  Command:
    minimap2 -ax map-ont -Y <Lib1> <File1>
    Output written to: output.sam

  Parameter rationale:
    -ax map-ont  - ONT preset: long reads with ~10-15% error rate;
                   uses homopolymer-aware k-mers and gap penalties
                   tuned for nanopore-characteristic indel noise.
    -Y           - Use soft clipping (rather than hard clipping) for
                   supplementary alignments, so that the full read
                   sequence is preserved in every SAM record; this is
                   critical for the downstream softclip extraction step.

Step 2 - Identify soft-clipped primary alignments
  (parse_sam_for_softclipped, long_read_tech='ont')

  Same filtering as the short-read case (primary alignment with 'S' in
  CIGAR), but when a read name has multiple primary-like records, the
  record with the highest AS score is retained rather than the first.
  This is important for ONT data where a single long read may generate
  several overlapping primary hits; choosing the best-scoring one
  maximizes the chance of correctly anchoring the main alignment.

Step 3 - Extract soft-clipped sequences
  Identical to the short-read case. Clipped sequences >= SEED_THRESHOLD
  are written to TEMP_READS.txt with _softclip_0 / _softclip_1 naming.

Step 4 - Iterative alignment  (run_iterative_ont_alignment(long_read_tech))

  All three long-read modes (ont/pb/hifi) iterate re-alignment via this
  same function -- earlier, only ONT did; PacBio CLR/HiFi were unified
  onto it after their single-round, whole-read-preset rescue was found
  to fail outright on short extracted fragments (confirmed empirically:
  a 167bp fragment came back unmapped under map-pb but aligned cleanly,
  MAPQ 60, under the short-fragment preset below). The loop runs up to
  6 rounds (max_rounds = 6; successful rescues converge by round 3-4 in
  practice) and terminates early when a round produces no new
  softclipped sequences.

  Round 2+ alignment command (is_initial=False):
    ONT / PacBio CLR:
      minimap2 -ax sr -k 10 -w 5 -m 10 -n 2 -A 2 -B 2 -O 2,4 -E 2,1
               --end-bonus 5 -s 20 -z 200 -r 50
               <Lib1> ./Test_Data/TEMP_READS.txt
    PacBio HiFi: same preset with -k 15 (lower error rate supports a
      larger, more specific minimizer; k=10 is tuned for the ~85%-
      accuracy ONT/CLR regime).
    Output written to: TEMP_SAM

  Note: although the data originated from a long-read technology, the
  re-alignment of soft-clip fragments uses a short-read-style preset
  (-ax sr base). The rationale is that soft-clip fragments are short
  (>= SEED_THRESHOLD but much shorter than the original read) and must
  be mapped precisely to identify the exact recombination breakpoint;
  the relaxed error model of the whole-read long-read presets would
  produce false-positive placements, or fail to map at all, at this
  scale.

  Before each round's output is merged, rewrite_embedded_insertions_as_
  softclips() runs on it too (not just the initial alignment) -- a
  rescued fragment can itself contain an embedded chimeric segment that
  needs a further round to resolve.

  When a softclip came from that rewrite (tagged via a ZI:i: SAM field
  recording the embedded insertion's own length), it is split into TWO
  independent realignment candidates instead of one glued fragment:
  <name>_softclip_<pos>_ins (the insertion content alone) and
  <name>_softclip_<pos> (everything after it alone, unchanged name).
  Gluing them is only unambiguous when the insertion's true origin and
  the following flank fall in increasing reference order; when the
  donor is on the other side, the glued fragment contains a real
  backward jump internally and minimap2 resolves it as one confident,
  silently-wrong placement (anchored on the longer piece) rather than
  leaving a softclip for the rescue mechanism to notice. Both candidates
  land at the same fractional sequence-position (see below) so the
  existing two-segment merge logic pairs them; a corresponding exemption
  in redundant-segment dedup keeps them from being collapsed back into
  one, since they are expected to overlap heavily in reference space by
  design (not treated as competing duplicates).

  Each iteration:
    a. TEMP_SAM is merged into output.sam (merge_temp_sam_to_output).
    b. TEMP_SAM is then re-scanned for mapped reads that still carry
       soft clips (FLAG bit 4 not set AND 'S' in CIGAR).
    c. New soft-clipped sequences >= SEED_THRESHOLD are extracted and
       named with nested labels (e.g., ReadName_softclip_1_softclip_0)
       to track their ancestry through the split-read tree.
    d. These sequences are written to TEMP_READS_R<N>.txt and aligned
       in the next round.
    e. Temporary files from the previous round are deleted to free disk.

  Sequence-space positions for nested clips use a fractional scheme:
    main alignment          = 0.5
    main_softclip_0         = 0.4 (before main)
    main_softclip_1         = 0.6 (after main)
    main_softclip_0_softclip_1 = 0.45 (between softclip_0 and main)
  Each additional nesting level halves the offset, ensuring correct
  ordering without explicit read-coordinate tracking.

Step 5 - Merge and convert
  After the iterative loop ends, convert_to_virema_format() is called
  on the merged output.sam. The merging and conversion logic is
  identical to the short-read case (Steps 5-6 above), but reads may
  now have more than two segments due to multiple rounds of extraction.

Step 6 - Compilation
  Identical to the short-read case.


------------------------------------------------------------------------
SITUATION 3: python ViReMa.py --Aligner minimap2 -lr pb
             (PacBio CLR Mode, LongReadTech = 'pb')
------------------------------------------------------------------------

Step 1 - Initial alignment (build_minimap2_command, long_read_tech='pb',
                             is_initial=True)

  Command:
    minimap2 -ax map-pb <Lib1> <File1>
    Output written to: output.sam

  Parameter rationale:
    -ax map-pb   - PacBio CLR preset: long reads with ~10-15% error
                   rate dominated by substitutions (unlike ONT which is
                   dominated by indels); tuned k-mer size and scoring
                   accordingly. The -Y flag is NOT used here, so
                   supplementary alignments may carry hard clips.

Step 2 - Identify soft-clipped primary alignments
  (parse_sam_for_softclipped, long_read_tech='pb')

  Same AS-score-based selection as ONT (keep the alignment with the
  highest AS among primary-like records for a read name) -- this was
  originally "use the first record" for pb/hifi, unified with ONT's
  behavior once the difference was found to matter for iterative
  rescue quality.

Step 3 - Extract soft-clipped sequences
  Identical to the ONT case, including the embedded-insertion rewrite
  and insertion/rest split described in Situation 2, Step 4.

Step 4+ - Iterative alignment (run_iterative_ont_alignment('pb'))

  PacBio CLR now shares ONT's iterative rescue loop (max 6 rounds) and
  short-fragment re-alignment preset (-k 10, same as ONT -- see
  Situation 2, Step 4) rather than reusing map-pb for rescue. Reusing
  the whole-read map-pb preset for short extracted fragments was found
  to fail outright (a 167bp fragment came back completely unmapped
  under map-pb but aligned cleanly, MAPQ 60, under the short-fragment
  preset), which was the primary reason PacBio CLR recall lagged ONT
  despite comparable error rates.

Step 5 - Merge and convert
  merge_temp_sam_to_output() and convert_to_virema_format() are called
  identically to the short-read case.

Step 6 - Compilation
  Identical to the short-read case.


------------------------------------------------------------------------
SITUATION 4: python ViReMa.py --Aligner minimap2 -lr hifi
             (PacBio HiFi Mode, LongReadTech = 'hifi')
------------------------------------------------------------------------

Step 1 - Initial alignment (build_minimap2_command, long_read_tech='hifi',
                             is_initial=True)

  Command:
    minimap2 -ax map-hifi <Lib1> <File1>
    Output written to: output.sam

  Parameter rationale:
    -ax map-hifi - PacBio HiFi preset: long reads with a much lower
                   (~99%+) per-base error rate than CLR/ONT (built-in
                   minimap2 preset, no manual overrides). The -Y flag
                   is not used here either.

Steps 2-6 - Identical to PacBio CLR (Situation 3) in every respect
  except the round-2+ re-alignment preset uses -k 15 instead of -k 10
  (see Situation 2, Step 4 for the rationale: HiFi's lower error rate
  supports a larger, more specific minimizer without losing sensitivity).


------------------------------------------------------------------------
COMPILATION PHASE  (Compiler_Module.py: ResultsSort; all three modes)
------------------------------------------------------------------------
After convert_to_virema_format() writes the final SAM, ViReMa.py calls
Compiler_Module.ResultsSort(cfg.Output_Dir + cfg.File3).

Pre-compilation steps (ViReMa.py):
  1. ExtractRefData(): calls bowtie-inspect to retrieve the full
     nucleotide sequence of each reference in Lib1. The sequences are
     stored in cfg.Genes and used later to annotate junction contexts.
  2. Optionally, UniquifyReport() removes PCR duplicates by collating
     alignment coordinates across multi-segment reads and discarding
     records with identical coordinate sets.
  3. If -BED12 is set, FindCoveragefromBED() reads a samtools depth
     file to populate per-position coverage arrays (cfg.RefsLib1_Coverage)
     used to annotate junction flanking coverage in the BED output.

ResultsSort() logic:
  The compiled SAM is read line by line. For each read:

  Single-segment reads (no TC:i tag):
    - Reads with only match/mismatch operations (no N gaps) are counted
      as coverage.
    - Reads with N gaps in their CIGAR represent recombination events:
        * If the gap size <= MicroInDel_Length: micro-deletion (D event)
        * If the gap size  > MicroInDel_Length: recombination/splice (N event)
      These are sorted into per-reference dictionaries.
    - Reads with I operations (insertions) are tallied separately.

  Multi-segment reads (TC:i:N tag, with FI:i fragment index):
    - All N segments are read together as a group.
    - The donor site (end of segment 1) and acceptor site (start of
      segment 2) are extracted from the RNAME/POS fields and the CIGAR.
    - The donor and acceptor reference names determine the event class:
        * Same reference, forward strand: deletion or recombination
        * Same reference, one reverse-strand: copy-back / snap-back
          (the long-read minimap2 path now propagates a reverse-strand
          segment here when minimap2 itself found one and the
          softclip-rescue mechanism isolated it as its own segment --
          see FIXED note at the end of this document. Whether the
          rescue mechanism isolates a given inversion in the first
          place is a separate, still-open question -- see the same
          note)
        * Different references: intergenic fusion / virus-to-host event
    - Compound recombination handling (if enabled): the unaligned
      nucleotides between two recombination junctions are searched in
      the genomic sequence between the donor and acceptor sites. A match
      indicates a compound (nested) recombination event, and the single
      N-gap event is split into two events at the matched position.
    - Long-read mode only: when two segments are separated by a small
      residual (below Seed) that doesn't cleanly meet the "adjacent
      segments" test above, the Donor/Acceptor jump is still classified
      as Recombination/MicroDeletion/MicroInsertion (mirroring the
      clean-adjacency logic exactly) rather than discarded as
      UnknownInsertion -- previously, ANY non-pixel-perfect adjacency
      fell through to UnknownInsertion, which reported only the small
      residual's own (uninformative) length and lost the real event
      entirely. The residual itself is also separately recorded as its
      own MicroInsertion. Guarded to only fire when the Donor/Acceptor
      are recognized reference names, working around a separate,
      pre-existing field-misalignment issue for reads with 3+ segments
      (documented in git history as a fix for reference names like
      "NC_004144_FHV_RNA2.seq" landing where a numeric position was
      expected).

  Output files written by WriteFinalDict():
    - Virus_Recombination_Results.txt and .bed: all within-virus
      recombination events (deletions, insertions, back-splices).
    - Virus_MicroIndel_Results.txt and .bed: small indels
      (size <= MicroInDel_Length).
    - Virus_Fusions_Results.txt and .bed: inter-segment or
      inter-reference recombination events.
    - Host_Recombination_Results.txt, Host_Fusions_Results.txt etc.:
      equivalent files for host-genome events (if --Host_Index is used).
      NOTE: --Host_Index (and --Host_Seed) are a dead end with the
      minimap2 aligner, short- or long-read mode. Minimap2_Module.py has
      no host-genome alignment step at all, so no read is ever aligned
      against the host genome and these files stay empty; the flags only
      do anything with --Aligner bowtie/bowtie2/bwa.

  Each BED entry includes:
    - Donor and acceptor coordinates (0-based BED convention; for a
      same-chromosome Deletion/Duplication these come out as raw
      Donor/Acceptor site order, i.e. NOT necessarily sorted
      start<=end the way strict BED format expects for a Duplication)
    - Event count (number of supporting reads)
    - Strand
    - Flanking nucleotide context (Seed nt on each side of junction)
    - Optional pseudo-reference sequence (if --PseudoRef is set)
    - Optional flanking coverage (if -BED12 or --Coverage_Offset is set)

  NOTE: WriteFinalDict() has two code paths depending on -ReadNamesEntry,
  and until this was fixed, the -ReadNamesEntry path never called
  WritetoBEDFile() at all -- BED output was silently empty for any run
  using -ReadNamesEntry (which includes every -lr run that also wants
  per-read attribution). Both paths now call WritetoBEDFile()
  identically.

  Also NOTE: BED NAME classification (Deletion/Duplication/Insertion/
  Intergenic-Fusion) is a Donor-vs-Acceptor position/strand comparison
  applied to whatever event class the run happens to produce; it has no
  vocabulary for the newer event classes this pipeline can now generate
  (same-chromosome distant insertions come out labeled Deletion or
  Duplication depending on jump direction -- mathematically correct
  direction, semantically not what either word means). A genuine
  reverse-strand segment reaching the classifier is now labeled
  correctly (see FIXED note below) rather than always coming out as
  Deletion.


------------------------------------------------------------------------
COMPARISON OF THE FOUR MODES
------------------------------------------------------------------------

Feature                 Short-read      ONT             PacBio CLR      PacBio HiFi
-----------------------  --------------  --------------  --------------  --------------
Initial preset           -ax sr(custom)  hand-tuned -a   -ax map-pb      -ax map-hifi
                                          flags, -Y
Softclip selection       First record    Highest AS      Highest AS      Highest AS
Embedded-insertion       No              Yes             Yes             Yes
  rewrite + ins/rest
  split
Re-alignment preset      -ax sr(relaxed) -k 10 (relaxed) -k 10 (relaxed) -k 15 (relaxed)
Iterative re-alignment   No (1 round)    Yes (up to 6x)  Yes (up to 6x)  Yes (up to 6x)
Nested clip naming       _softclip_0/1   _softclip_0/1   _softclip_0/1   _softclip_0/1
                                         (+ recursive, + _ins variants for all three)
Compilation              Identical       Identical       Identical       Identical

All four modes write a ViReMa-compatible SAM in which each split read is
represented either as a single record with N gaps in the CIGAR (for
contiguous recombination on the same reference) or as a primary plus
supplementary record pair with hard clips (for cross-reference or
back-splice events). The downstream Compiler_Module is unaware of
which aligner mode was used.


------------------------------------------------------------------------
FIXED: strand information was discarded before classification
------------------------------------------------------------------------
Investigated while testing inversion detection. minimap2 correctly finds
reverse-strand alignments for inverted content once it has been isolated
by the softclip-rescue mechanism above (confirmed directly: an isolated
inversion candidate aligned at flag=16 (reverse), MAPQ=60, at the true
inversion boundary) -- and Compiler_Module.py's classifier already has
working _RevStrand-aware logic to turn that into a distinct event class
(it is exercised correctly by the short-read pipeline, which tags
reverse-strand segments via the SAM FLAG at conversion time -- see
ViReMa.py's short-read SAM-to-ViReMa conversion path).

The long-read (Minimap2_Module.py) conversion path previously did not
propagate this: three separate record-construction sites unconditionally
hard-coded the SAM strand flag to forward before the record ever reached
classification (convert_single_read, create_single_merged_record_new,
create_paired_records_new). This is now fixed -- all three preserve
strand.

The fix needed one subtlety beyond simply not hard-coding the flag.
Every merged/paired record is built from primary_read.copy(), so its
SEQ field is always primary_read's own SEQ -- a fixed shared frame. A
segment's raw SAM strand bit is relative to the *original as-sequenced
read*, not to that frame. For the primary segment itself the two happen
to be different things: whatever minimap2 reported for the whole read's
own strand during the initial search is irrelevant once primary_read's
SEQ becomes everyone's shared frame -- by construction, the primary
segment's own CIGAR is always forward relative to its own SEQ. Treating
its raw absolute flag as the record's strand instead of always 0 caused
a real, measured regression on ordinary (non-inversion) DUP/CISINS
benchmark cells: since long-read sequencing is strand-agnostic, roughly
half of all reads have their whole-read primary alignment reported
reverse for no event-related reason, and the naive fix spuriously
flipped the Donor/Acceptor junction side used for position calculation
whenever that happened. Independently re-aligned rescue segments don't
have this problem -- their own reported flag, from a call that queried a
literal substring of primary_read's SEQ, is already relative to the
correct shared frame, so it's used as-is.

_segment_strand() (Minimap2_Module.py) now implements exactly this:
returns 0 unconditionally for the 'main'/primary segment, and the
segment's own true SAM strand bit for everything else. Verified against
the DUP-100bp, CISINS-1000bp, and DEL-1000bp benchmark cells: TP/FP now
match the pre-fix baseline exactly (DUP 19/64, CISINS 108/149) or are
consistent with prior validated performance (DEL 65/66) -- i.e. the
regression is fully resolved, not merely reduced.

SEPARATE, STILL-OPEN ISSUE: testing this fix against a real synthetic
inversion (a 1000bp reverse-complemented block in a ~30kb reference)
through the actual production entry point (ViReMa.py directly, not a
hand-rolled pipeline replay used during initial debugging) shows the
ONT preset's very cheap gap costs (-O 2,32 -E 1,0 -z 200 -g 2000, tuned
to prefer long deletions) make it *cheaper* for minimap2 to plow
straight through the reverse-complemented block as a dense run of
small-indel noise within one alignment record than to soft-clip it out.
With no softclip produced, the rescue mechanism never gets a chance to
act on that region at all -- there is nothing to re-align, so this
strand fix has nothing to preserve. So while strand information is no
longer discarded once found, genuine inversion detection for an
inversion of this size is not demonstrated to work under the current
ONT preset. This looks like a separate, alignment-parameter-tuning
problem, not a classification/strand-propagation problem.
